# 旅游知识库分类与检索

分类由 PostgreSQL 的 `knowledge_category` 表维护，前端通过
`GET /api/v1/knowledge/categories` 获取树形结构，因此新增或调整分类不需要重新编译前端。

## 初始化/迁移

已有数据库执行：

```bash
psql "$DATABASE_URL" -f scripts/init_db.sql
```

使用 Alembic 的环境执行：

```bash
alembic upgrade head
```

当前分类树（由数据库动态返回）为：

```text
全部知识
├── 目的地
│   └── 景点与城市
├── 旅游攻略
│   └── 行程攻略
├── 吃住行
│   ├── 美食
│   ├── 住宿
│   └── 交通
├── 旅游经验
│   └── 实用经验
└── 旅游资讯（实时内容不进入管理员正式列表）
    ├── 景区与活动
    └── 旅游动态
```

升级已有数据库时执行 `alembic upgrade head`，其中
`0003_compact_categories` 会把旧分类的分片 metadata 自动映射到
上述合并后的叶子分类，不需要重新上传文档。

知识分片的 `metadata` 保存 `category`（一级分类）、`sub_category`（叶子分类）、
`city`、`province`、`season`、`travel_type`、`source` 和 `update_time`。管理员上传
文档时这些字段随分片写入；公网搜索只保存重排后的前两个分片。景区公告、交通动态、
节假日活动和文旅新闻按分类的 `ttl_hours` 写入 `knowledge_document.expires_at`，过期文档
不会参与检索。

PGVector 查询会先按分类、城市、省份、季节和出行类型过滤，再按余弦距离排序；未提供
过滤条件时才对全部未过期 READY 文档进行向量检索。

## 公网内容入库闸门

公网搜索的所有结果都会作为本次回答的临时证据交给大模型，但持久化前还需依次通过：

1. 来源筛选：A级为政府/文旅局/景区官网等权威站点，B级为携程、马蜂窝、飞猪、去哪儿、同程、穷游、途牛、驴妈妈和大众点评等平台；个人博客、资讯聚合和广告站点不入库。
2. 内容清洗和质量评估：正文过短、广告词密集或明显模板化的内容会被过滤。
3. 语义去重：与现有 READY 分片余弦相似度达到 0.92 以上的内容不重复保存。
4. 时效判断：资讯类分片按分类 TTL 写入 `expires_at`；高铁车次、余票、路线等实时结构化数据直接由 MCP 提供，不持久化。

最终仅保存排序最前的 1～2 个、来源可信、内容完整、非重复且在有效期内的网页分片。
